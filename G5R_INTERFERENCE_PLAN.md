# G5R Stage D: separating route inference from online interference

Status: FROZEN before any code or endpoint exists (hash recorded in
`tools/check_prereg.py`). Successor to `G5R_DIAGNOSIS_PLAN.md`, whose frozen
classification was `ROUTE_INFERENCE_OR_ONLINE_INTERFERENCE_FAILURE` and which
stated that it "deliberately cannot separate route inference from sequential
training/replay interference". This plan separates them. It is a DEVELOPMENT
diagnostic on worlds 0-2. It cannot revise G5R's 0/3 online verdict, does not
tune anything, and opens no control-flow rung.

# The confound the previous stage left

Stage C trained the 12-slot rotated library with TRUE routes fixed for 4,096
AdamW updates at batch 64 (262,144 example-gradients) and passed 2/3 worlds. The
G5R lifetime takes 8,192 updates at batch <= 2 (one current example plus one
replay example; ~16,000 example-gradients). Stage C therefore differs from the
lifetime in THREE ways at once: it knows the routes, it sees tasks interleaved
rather than sequentially, and it spends ~16x more example-gradients. Its pass
cannot be attributed to any one of them, and the "route inference or
interference" label silently assumed budget was not the cause.

# Design: a 2 x 2 at the lifetime's own budget, plus the budget axis

Every cell uses the identical `RotatedDiscreteLibraryLearner` (canonical
`configs/v1.yaml` `discrete_model`: 12 slots, rank 8, 3 steps, alpha init 0.2
learnable, temperature 1.0 -> 0.1 global schedule, global LR 0.001, task LR
0.05, weight decay 1e-4 on non-alpha shared parameters, model seed 5000) on the
rotated `sigma = 0` worlds 0, 1, 2 generated by `rotated_world.py`. Only two
factors and one budget vary:

    ROUTES     x   SCHEDULE          budget          cell        status
    oracle         offline IID       lifetime        C_lo        NEW
    oracle         offline IID       Stage C         C_hi        EXISTS (Stage C, reused, not rerun)
    learned        offline IID       lifetime        L_lo        NEW
    learned        offline IID       Stage C         L_hi        NEW
    oracle         online lifetime   lifetime        O_or        NEW (three full lifetimes)
    learned        online lifetime   lifetime        O_lr        EXISTS (G5R artifacts, rescored, not rerun)

- ORACLE routes: each task's code is pinned to its true route through the
  Stage-C slot assignment (`assign_slots`, lowest unused slot in the matching
  O(d) component), logits +50 / -50, `requires_grad = False`. At every
  temperature in [0.1, 1.0] the float32 softmax of that code is exactly one-hot,
  so training and evaluation use the same hard route. Teacher identities are
  used ONLY inside these explicitly labelled oracle arms.
- LEARNED routes: codes start at zero, train at task LR 0.05, soft during
  training, argmax at evaluation -- exactly the lifetime's discrete learner.
- OFFLINE IID: one batch per update drawn with replacement from the union of
  all 64 tasks' 8,192 training examples, from
  `SeedSequence([1702, world, cell_index])`; all 64 task codes exist from
  update 0. Temperature progress is `update / (updates - 1)`, the lifetime's
  global schedule with updates in place of examples.
- ONLINE lifetime: the UNCHANGED `learned_lifetime.run` loop -- score before
  update, one update per example, 1:1 replay of four retained examples per
  task, artifacts, checkpoint probes -- with the only addition being an
  optional `task_code_hook(model, task, world_task_index)` invoked immediately
  after `begin_task`, `None` for every existing caller. O_or uses it to pin
  the oracle code; nothing else in the loop changes.
- LIFETIME budget: 8,192 updates at batch 2. STAGE C budget: 4,096 updates at
  batch 64 (the frozen Stage C constants, imported from the Stage C module, not
  retyped).
- Optimizer for offline cells: AdamW with the lifetime's three groups (shared
  non-alpha with weight decay 1e-4, alpha without decay, task codes at LR 0.05
  without decay), built by `_shared_optimizer` plus one task-code group, so it
  is the lifetime's optimizer rather than a lookalike.

# Estimand and thresholds

For every cell the statistic is the Stage C statistic: the MEDIAN over the 64
training tasks of query NMSE on each task's frozen evaluation examples under the
hard route (oracle or argmax), computed by one shared scorer applied to the
terminal model. Threshold `<= 0.05` per world (Stage C's), pass rule `>= 2/3`
worlds (the frozen family rule). Per-world outcomes are reported in full because
world 0 dissented in Stage C.

Offline cells also record the statistic at updates 0, 256, 1024, and the final
update (and 4,096 for the lifetime-budget cells) so trajectories can be compared
with Stage C's.

# Decision ladder (registered)

Let PASS(cell) mean the >= 2/3-world rule holds.

1. **If C_lo FAILS:** classification `BUDGET_LIMITED`. With true routes and no
   sequential structure the lifetime's gradient budget is insufficient, so the
   previous stage's dichotomy was not the binding constraint at that budget.
   The other cells are still run and reported descriptively; L_hi then says
   whether learned routes are feasible when budget is not binding.
2. **Else (C_lo passes):**
   - O_or fails and L_lo passes: `ONLINE_INTERFERENCE`.
   - O_or passes and L_lo fails: `ROUTE_INFERENCE`.
   - both fail: `BOTH_INDEPENDENTLY_SUFFICIENT`.
   - both pass: `INTERACTION_ONLY` -- neither factor alone is fatal at this
     budget; only their combination (G5R) is.

L_hi is secondary in every branch: a pass says route inference is a budget
matter offline; a fail says learned routing fails even with Stage C's budget.

# Registered predictions

- C_lo: genuinely uncertain, near even. Stage C was still at median 0.87-0.92
  after 1,024 updates (65,536 example-gradients); the lifetime has 8,192 updates
  but only ~16,000 example-gradients. If step count dominates, C_lo passes; if
  example count dominates, it fails.
- Conditional on C_lo passing: O_or fails (0.6) and L_lo fails (0.65), so the
  modal prediction is `BOTH_INDEPENDENTLY_SUFFICIENT`, then
  `ONLINE_INTERFERENCE`.
- L_hi: fails more often than not (0.6). The G5R learner used all 12 slots with
  confident routes (mean max coefficient 0.79-0.80) yet recovered zero explained
  routes on world 0, which reads as confident wrong routing rather than diffuse
  routing.
- World 0 remains the worst world in every cell.

# Non-vacuity and equivalence checks (must pass before any verdict)

- ANCHOR: the shared scorer applied to the existing G5R artifacts must
  reproduce each artifact's own per-task `final_nmse` to 1e-6 (same model, same
  evaluation examples, argmax routes). If it does not, the scorer measures
  something else and nothing is read.
- PINNING: in O_or, the terminal hard routes of all 64 tasks equal the oracle
  routes, and the pinned softmax at temperature 1.0 is exactly one-hot.
- LEARNING: in every new cell, the terminal shared parameters differ from
  initialization (relative change > 0), and every loss is finite.
- RELOAD: the O_or statistic is computed from the model reloaded from its
  artifact, after `validate_artifact` against the resolved config.
- One writer per cell; the report is written atomically after each cell with a
  protocol fingerprint (budgets, batch sizes, LRs, seeds, thresholds, frozen
  plan) and a cell computed under a different fingerprint is refused.

# Arms as constructions (review 82)

    cell   init     shared trainable   codes           optimizer      updates x batch
    C_lo   seed     yes                pinned, frozen  lifetime AdamW 8192 x 2
    L_lo   seed     yes                zero, LR 0.05   lifetime AdamW 8192 x 2
    L_hi   seed     yes                zero, LR 0.05   lifetime AdamW 4096 x 64
    O_or   seed     yes                pinned, frozen  lifetime loop  8192 x <=2 (+replay)
    C_hi   seed     yes                pinned, frozen  Stage C AdamW  4096 x 64   (reused)
    O_lr   seed     yes                zero, LR 0.05   lifetime loop  8192 x <=2  (reused)

Note the one deliberate asymmetry: C_hi used the Stage C module's `_adamw`,
which places task codes (frozen there anyway) and shared parameters in one
group at LR 0.001. For pinned codes that is identical to the lifetime optimizer,
so C_hi and C_lo differ only in budget.

# Artifacts and validation

Report `reports/rotated_g5r_interference.json`. O_or writes full lifetime
artifacts to `artifacts/g5r_interference/oracle_online/world_{k}/` with an
intervention stamp, following G5R's `_load_or_run` discipline (a summary with a
missing or mismatched stamp is fatal). Offline cells store their terminal
statistics and trajectories in the report only. Accept the result only after:
exit code 0; three worlds in every new cell; the anchor, pinning, learning, and
reload checks; all-finite metrics; report freshness and a frozen-code commit;
the unit tests; `git diff --check`; `tools/check_prereg.py`; and
`tools/check_invalid.py`.

# Cost

Offline lifetime-budget cells are minutes each. L_hi is comparable to one Stage
C world. O_or is three full lifetimes, about two hours each, run as a bounded
pool of three (the discrete learner is a light model).

# What this plan cannot establish

It cannot rescue G5R, rank optimizers, or show that a different online protocol
would learn the rotated family. If `BUDGET_LIMITED` is returned, it does not
say what budget would suffice. It localizes the failure one level further so a
successor protocol, if any is ever registered, is chosen from evidence.

# Amendment 1 (2026-09-02, before any Stage D code): the anchor quantity

Found while inspecting the G5R artifacts to build the anchor check. The
lifetime's per-task `final_nmse`, and therefore G5R's headline medians
(1.763 / 1.613 / 1.696), are measured at the END OF EACH TASK'S OWN TRAINING
(the `n_seen = 128` evaluation record), not on the terminal model. Only the
LAST task's value is a terminal-model quantity. The anchor clause as written
("reproduce each artifact's own per-task `final_nmse`") is therefore
unsatisfiable for 63 of 64 tasks and would have failed for the wrong reason.

Registered replacement, unchanged in intent:

- ANCHOR: the shared scorer applied to the reloaded G5R terminal model must
  reproduce the LAST task's `task_summary.final_nmse` to 1e-6 in each world.
- The registered estimand for every cell remains the TERMINAL-MODEL median. For
  the two online cells (O_or, O_lr) the END-OF-TASK median is reported beside
  it, labelled as such, because that is the quantity G5R's verdict used and
  because their difference (terminal minus end-of-task) is a direct
  interference measurement: how much a task's fit degrades after its own
  training ends. No threshold is attached to that difference; it is
  descriptive.
