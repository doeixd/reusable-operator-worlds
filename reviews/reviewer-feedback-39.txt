Yes. Thinking about the whole arc, I think we're converging on something more specific than "neural library learning."

The missing centerpiece is **hypothesis-driven program induction in a learned language**.

The system shouldn't merely recognize patterns, retrieve skills, or compress computations after solving tasks. It should be able to say, in effect:

> "Maybe this situation is generated by *this* program, under *this* way of representing it. What follows if that's true?"

Then it executes the hypothesis forward, compares its consequences with reality, modifies or rejects it, and eventually changes its own vocabulary if the current vocabulary makes too many problems difficult.

That gives us a fairly coherent theory of **reasoning, theorizing, perception, dreaming, planning, abstraction, and insight**.

DreamCoder is an important ancestor here: it alternates program solving with library growth and training a neural search policy; later work explicitly describes the neural search policy as amortizing search breadth while learned abstractions reduce search depth. But it largely works with symbolic program languages supplied by the researcher. ([arXiv][1]) Our project is trying to push the boundary much further: **learn the actual computational vocabulary, including neural/perceptual operations, and allow that vocabulary itself to restructure according to its prospective usefulness.** Recent work on prospective compression in human abstraction learning is interestingly aligned with the idea that abstractions should be selected according to anticipated future usefulness rather than merely retrospective corpus compression. ([arXiv][2])

I think there are about **ten fundamental questions** between where we are and that system.

---

## 1. What exactly is a "program" in our architecture?

This sounds trivial, but it's foundational.

Right now we can imagine:

[
P=A_4\circ A_3\circ A_2\circ A_1.
]

Eventually that isn't enough.

Real reasoning needs things like:

[
\operatorname{IF}(C,A,B)
]

[
\operatorname{MAP}(A,S)
]

[
\operatorname{REPEAT}(A,\text{until }C)
]

[
\operatorname{SELECT}(S,P)
]

[
\operatorname{CALL}(A,x,y)
]

plus variables, references, temporary objects and memory.

So one major question is:

> **What is the minimal computational substrate we should give the learner, versus what should the learner itself discover?**

I increasingly think we should **not** make the system discover computation from absolute scratch.

Give it something analogous to an instruction set:

[
{\text{CALL, COMPOSE, BRANCH, BIND, READ, WRITE, ITERATE, HALT}}.
]

But don't give it:

[
{\text{OBJECT, SYMMETRY, PLAN, COLLISION, COUNT, SEARCH},...}.
]

Those should be learned.

The distinction would be:

[
\boxed{
\text{fixed computational mechanics}
\quad+\quad
\text{learned computational vocabulary}.
}
]

That's analogous to giving humans working memory and basic control machinery without giving them calculus.

A crucial V6-ish experiment is therefore **compositional closure**: can neural library operators be safely connected into programs much deeper than those seen during training? If error explodes at depth 5, the entire AGI story is in trouble.

---

## 2. What does it mean to hypothesize a program?

I think we need a population of candidate explanations:

[
H_t={P_1,P_2,\ldots,P_k}.
]

Given evidence (D), we don't immediately choose one.

We maintain something like:

[
S(P)
====

L(P\mid\mathcal L)
+
L(D\mid P)
+
\alpha C_{\rm synth}(P)
+
\beta C_{\rm execute}(P).
]

Then reasoning searches around these hypotheses.

A candidate can be modified:

[
P\rightarrow P'
]

by:

* replacing an operator;
* changing an argument;
* inserting an operator;
* changing the perceptual decomposition;
* introducing a conditional;
* generalizing a constant into a parameter;
* inventing a temporary primitive.

The crucial difference from ordinary neural inference is that the candidate is **executable**.

You can ask:

[
P(s,a)=?
]

and see what follows.

So I'd define:

[
\boxed{
\textbf{a theory is a compact executable hypothesis that predicts consequences.}
}
]

Program induction from examples already gives a precedent for treating concepts and solutions as latent programs; DreamCoder and Bayesian program-learning work demonstrate the basic feasibility of composing learned/library concepts in this way, though with much more hand-specified representational structure than we're proposing. ([arXiv][1])

---

## 3. How does the model discover a *different way of looking at the same thing*?

I think this might be one of the deepest problems in the project.

Suppose an ARC-like grid contains 40 colored cells.

Representation (R_1):

[
40\text{ cells}.
]

Representation (R_2):

[
4\text{ objects}.
]

Representation (R_3):

[
2\text{ repeating tiles}.
]

Representation (R_4):

[
1\text{ shape under a symmetry group}.
]

Same data.

Radically different program complexity.

So we should jointly infer:

[
(R^*,P^*)
=========

\arg\min_{R,P}
\left[
L(R)+L(P\mid R)+L(D\mid P,R)
\right].
]

This means **perception is part of program synthesis**.

The model isn't asked:

> What objects are here?

It's asked:

> Under what decomposition does what is happening become simple?

That's a much deeper criterion for perceptual abstraction.

And it immediately gives us an experiment.

Construct worlds where the raw observation supports multiple perfectly valid decompositions, but only one decomposition yields a short predictive/action program.

Then ask whether MDL pressure causes the system to invent the useful perceptual operator.

If yes:

[
\boxed{
\textbf{perception can emerge from pressure for simple downstream computation.}
}
]

That's a huge result if we can demonstrate it cleanly.

---

## 4. How do new primitives get invented rather than merely extracted?

This is an important distinction.

V3 PROMOTE is close to:

[
\text{notice recurring functional computation}
\rightarrow
\text{name it}.
]

But scientific/theoretical abstraction is stronger.

Sometimes the good primitive may never literally have occurred as a repeated subgraph.

Suppose:

[
P_1=A(\alpha_1)+\epsilon_1
]

[
P_2=A(\alpha_2)+\epsilon_2
]

[
P_3=A(\alpha_3)+\epsilon_3.
]

The system should invent:

[
A(\alpha)
]

even though no one program contained the generic parameterized (A).

That's **anti-unification/generalization**, not extraction.

Symbolic library-learning work already wrestles with this distinction: Stitch searches for abstractions that compress corpora, while Babble uses equivalence-aware anti-unification so syntactically different but semantically related programs can expose reusable structure. ([arXiv][3]) Our neural version has the harder gauge/substitutability problem V3 exposed, so we'd need to discover such abstractions in **functional space**, not by parameter matching.

I would eventually give sleep several candidate mutation operators:

[
\texttt{EXTRACT}
]

[
\texttt{GENERALIZE}
]

[
\texttt{PARAMETERIZE}
]

[
\texttt{FACTOR}
]

[
\texttt{MACRO}
]

and let economics determine which survives.

---

## 5. What exactly is "dreaming"?

I think we should stop using the word loosely and give it a technical meaning.

### Dreaming = counterfactual execution without immediate external observation.

Given:

[
(P,s_t),
]

run:

[
\hat s_{t+1}=P(s_t,a_t)
]

[
\hat s_{t+2}=P(\hat s_{t+1},a_{t+1})
]

and so on.

This has at least three conceptually distinct uses.

**Planning:** "What happens if I do this?"

**Theory testing:** "If my explanation is true, what else must be true?"

**Abstraction discovery:** "If I compose these concepts in hypothetical circumstances, what structure appears?"

Model-based RL systems such as Dreamer demonstrate that learned latent world models can support action learning from imagined trajectories, so the basic idea that internal rollouts can be computationally useful is well established. ([arXiv][4]) Our distinction would be that the imagined transition model itself may be a **synthesized program assembled from learned primitives**, rather than one monolithic learned dynamics network.

But this immediately exposes a dangerous issue:

### Dreams are not evidence.

If:

[
P
]

generates dream (D_P),

then evaluating:

[
P
]

against (D_P) tells us nothing.

Otherwise the system can literally hallucinate evidence for its own theories.

So we'd need a constitutional rule:

[
\boxed{
\textbf{Dreams may propose, train search, and expose consequences; external or held-out evidence must adjudicate hypotheses.}
}
]

That distinction feels extremely important.

---

## 6. How does the model turn theorizing into experimentation?

Suppose:

[
P_1
]

and:

[
P_2
]

both explain everything observed.

But under action (a):

[
P_1(s,a)\neq P_2(s,a).
]

Then the intelligent thing is not merely to keep thinking.

It is to choose (a).

So:

[
a^*
===

\arg\max_a
\mathbb E[
\text{discrimination among }H
].
]

This converts:

[
\text{program synthesis}
]

into:

[
\boxed{\text{active program induction}.}
]

Recent work explicitly studies active visual concept induction in environments where agents must form, test, and revise hypotheses through experimentation, and work on synthesized queries similarly explores choosing observations that discriminate candidate programs. ([arXiv][5])

For us, this could be an absolute beautiful intermediate benchmark.

Give the model two hidden world programs that are indistinguishable under passive observations.

Only one particular experiment separates them.

Then test:

[
\text{observe}
\rightarrow
\text{hypothesize}
\rightarrow
\text{dream both}
\rightarrow
\text{find disagreement}
\rightarrow
\text{experiment}.
]

That's **scientific reasoning in miniature**.

---

## 7. Can reasoning strategies themselves become primitives?

This is where I think the project becomes especially interesting.

Initially, solving a problem may involve an ugly search trace:

[
\text{propose}
\rightarrow
\text{simulate}
\rightarrow
\text{compare}
\rightarrow
\text{backtrack}
\rightarrow
\text{propose}
\rightarrow\cdots
]

Across thousands of tasks, perhaps this pattern keeps appearing:

[
\text{work backward from target}
\rightarrow
\text{identify necessary predecessor}
\rightarrow
\text{repeat}.
]

Eventually MDL should ask:

> Why are you repeatedly paying to rediscover this reasoning strategy?

Then:

[
\operatorname{PROMOTE}(\text{trace motif})
\rightarrow
\texttt{BACKWARD_CHAIN}.
]

Likewise:

[
\texttt{FIND_INVARIANT}
]

[
\texttt{TRY_COUNTEREXAMPLE}
]

[
\texttt{DIVIDE_AND_CONQUER}
]

[
\texttt{SIMULATE_AHEAD}.
]

This would give a very concrete account of the emergence of "reasoning."

[
\boxed{
\textbf{Reasoning strategies are compressed regularities in successful search.}
}
]

And we'd have a brutal test:

After promotion, do **unseen task families** require fewer search expansions?

Not merely fewer tokens.

Not merely better performance.

Measure:

[
C_{\rm search}^{\rm before}
---------------------------

C_{\rm search}^{\rm after}.
]

If a supposed reasoning abstraction doesn't reduce prospective search on structurally novel problems, don't call it reasoning.

This also addresses a known danger in library-learning research: apparent improvements need not actually come from library reuse. One recent analysis of mathematical library-learning systems found tool reuse was very rare and attributed much of the gains instead to self-correction/self-consistency. ([arXiv][6]) Our project should be almost paranoid about measuring actual causal reuse.

---

## 8. Description length alone isn't enough: **search length matters**

I think this is a major theoretical upgrade.

Suppose two languages can both express (P).

In (\mathcal L_1):

[
P=A\circ B\circ C\circ D\circ E.
]

In (\mathcal L_2):

[
P=M.
]

Obviously:

[
L(P\mid\mathcal L_2)<L(P\mid\mathcal L_1).
]

But perhaps more important:

[
C_{\rm synth}(P\mid\mathcal L_2)
\ll
C_{\rm synth}(P\mid\mathcal L_1).
]

Good abstractions don't just compress solutions.

They make solutions **findable**.

LAPS explicitly separates these two ingredients in program synthesis—a useful function library and an efficient search strategy—and learns both library abstractions and search heuristics. ([arXiv][7]) DreamCoder-related work likewise frames library learning as reducing search depth and neural guidance as reducing breadth. ([arXiv][8])

For our project I would therefore replace the simplest MDL objective with something closer to:

[
\boxed{
J
=

L(D\mid P)
+
\lambda D^*(P,\mathcal L)
+
\alpha C_{\rm synth}
+
\beta C_{\rm execute}
+
\gamma C_{\rm learn}.
}
]

This has an important consequence:

> **An abstraction may be worth creating even if it barely reduces storage, because it radically reshapes the search landscape.**

That could turn out to be essential.

---

## 9. How do we prevent the program synthesizer from secretly becoming the whole intelligence?

This is perhaps the biggest architectural risk.

Imagine our "neural library" is modest, but we write an incredibly sophisticated MCTS/program synthesizer around it.

It solves ARC.

Have we demonstrated the theory?

Not really.

We've hand-coded intelligence into the search engine.

So we need an explicit decomposition:

[
\text{library quality}
]

versus:

[
\text{proposal quality}
]

versus:

[
\text{search compute}.
]

I would develop in this order:

[
\text{oracle synthesis}
\rightarrow
\text{generic brute-force/beam synthesis}
\rightarrow
\text{learned proposer}
\rightarrow
\text{learned search strategy}.
]

At every stage, freeze everything else.

Then measure exactly where the gain comes from.

Eventually successful search traces become training data for:

[
q_\phi(P\mid D,\mathcal L).
]

That is essentially amortizing deliberation.

And then something beautiful can happen:

[
\boxed{
\text{search discovers solutions}
\rightarrow
\text{neural policy learns where to search}
\rightarrow
\text{library compresses recurring discoveries}.
}
]

You get two forms of compilation:

[
\textbf{breadth compilation}
\rightarrow q_\phi
]

and:

[
\textbf{depth compilation}
\rightarrow\mathcal L.
]

That is closely related to what existing DreamCoder-derived work describes, but we'd be doing it over a learned neural computational language. ([arXiv][9])

---

## 10. When does the model decide that the *language*, rather than the current program, is wrong?

This may be the ultimate question.

Suppose a task is solvable, but every solution requires:

[
10^7
]

search expansions.

There are two possible conclusions:

> "I haven't searched hard enough."

or:

> "I'm thinking about this in the wrong language."

Humans seem capable of the second.

That is the difference between **problem solving** and **conceptual invention**.

We need an operational signal.

One candidate:

[
C_{\rm synthesis}(T\mid\mathcal L)
]

remains systematically large across related tasks.

Then sleep asks:

[
\mathcal L'
===========

\arg\min_{\mathcal L'}
\left[
D^*(\mathcal L')
+
\mathbb E_T C_{\rm solve}(T\mid\mathcal L')
\right].
]

Now the system is literally searching for:

> a language in which these problems become easier.

And I think this is the strongest interpretation of **insight** available to the project:

[
\boxed{
\textbf{Insight is a representation/language edit that causes the search problem to collapse.}
}
]

Before:

[
10^6\text{ candidates}.
]

After inventing (A):

[
12\text{ candidates}.
]

That's more meaningful than saying some hidden embedding changed.

# This makes the whole project look different

I now see **two nested search processes**.

### Inner search: reasoning

With library (\mathcal L), search:

[
P^*
===

\arg\min_{P\in\operatorname{Programs}(\mathcal L)}
J(P).
]

Question:

> What explains/solves this problem using what I know?

### Outer search: abstraction

Search:

[
\mathcal L^*
============

\arg\min_\mathcal L
\left[
D^*(\mathcal L)
+
\mathbb E_T C_{\rm solve}(T\mid\mathcal L)
\right].
]

Question:

> What should I know so that problems like this become easier to think about?

And then:

[
\boxed{
\mathcal L
\rightarrow
P
\rightarrow
\text{experience}
\rightarrow
\mathcal L'
\rightarrow
P'
\rightarrow\cdots
}
]

The inner process improves the outer one by generating useful reasoning trajectories.

The outer process improves the inner one by changing its language.

**That loop may be the actual research thesis.**

---

# It also clarifies the cognitive vocabulary

I wouldn't build separate modules called `reasoning`, `theory`, `dreaming`, etc.

They can be descriptions of what the same machinery is doing.

| Phenomenon          | Computational interpretation                                           |
| ------------------- | ---------------------------------------------------------------------- |
| **Perception**      | synthesize a representation program                                    |
| **Reasoning**       | search/execute programs under current representation                   |
| **Theorizing**      | propose executable generative programs explaining observations         |
| **Planning**        | execute candidate causal programs under hypothetical actions           |
| **Experimentation** | choose real observations/actions that discriminate programs            |
| **Dreaming**        | internally execute candidate programs/counterfactuals                  |
| **Learning**        | update task programs/search priors                                     |
| **Abstraction**     | alter the language to amortize recurring computation                   |
| **Insight**         | discover a representation that sharply reduces description/search cost |
| **Intuition**       | formerly expensive reasoning compiled into a cheap reusable program    |

That's a very coherent architecture.

# The next benchmark shouldn't be ARC yet

I think there is an intermediate benchmark we should build that is much more diagnostic.

Call it, provisionally, **Little Scientist Worlds**.

Generate tiny worlds from hidden programs.

The agent receives pixels or tokens and can perform actions.

Critically, worlds should be designed so that solving them requires progressively more of the loop.

**Rung A:** infer one hidden transformation.

**Rung B:** compose known primitives.

**Rung C:** choose among competing perceptual decompositions.

**Rung D:** two theories fit passive evidence; perform an experiment.

**Rung E:** current library expresses the rule awkwardly; invent a primitive.

**Rung F:** repeated reasoning/search pattern becomes worth compiling.

**Rung G:** a new task requires novel composition of learned perceptual + causal + reasoning primitives.

**Rung H:** transfer to a generator family never encountered during library learning.

The important thing is that every rung has an oracle.

We know the latent world program.

Therefore we can independently measure:

[
\text{program recovery},
]

[
\text{representation recovery},
]

[
\text{search cost},
]

[
\text{prediction},
]

[
\text{intervention efficiency},
]

[
\text{library growth},
]

and:

[
\text{prospective learning savings}.
]

Only after those pieces work should we throw ARC at it.

# There are some serious failure modes we should actively seek

This isn't guaranteed to work.

One failure would be **neural non-compositionality**:

[
A,B\text{ individually good}
\not\Rightarrow
B\circ A\text{ good}.
]

If that persists, we may need stronger contracts/adapters between primitives.

Another is **ontology lock-in**. Early abstractions could make later experience easy enough to explain that the model never discovers a radically better representation.

That suggests maintaining competing representations rather than one canonical worldview.

Another is **self-confirming dreams**, which is why imagined evidence cannot validate its generator.

Another is **search explosion**. A language may be expressive enough but unusable because synthesis is computationally intractable.

Another is **overcompression**: MDL can prefer a simple theory that predicts common cases but systematically misses rare important structure. The error code must price those failures properly.

Another is **single-use abstraction theater**: the model creates impressive named modules that are never causally reused. Existing library-learning work gives us reason to audit this explicitly. ([arXiv][6])

And V4 gives us another:

[
\boxed{
\text{apparent structural intelligence that disappears against the correct cheap counterfactual}.
}
]

Every one of those can become an experimental gate.

---

# One other idea: don't force a single ontology

This may matter a lot.

Humans can view the same object as:

* a physical object;
* a geometric shape;
* a tool;
* a collection of parts;
* an economic asset.

Different problems reward different descriptions.

So perhaps the mature library shouldn't converge to:

[
x\rightarrow z^*
]

where (z^*) is "the" true representation.

Instead it contains transformations:

[
R_1,R_2,\ldots,R_n
]

and program synthesis chooses the useful view.

Then abstraction becomes:

[
\text{learn new lenses}
]

rather than:

[
\text{discover the one correct latent space}.
]

That fits beautifully with your "different ways of looking at things" intuition.

The criterion is pragmatic but principled:

[
\boxed{
\text{A way of seeing is useful insofar as it makes successful theories/programs cheaper.}
}
]

---

# And I think V4 tells us how this language should evolve

This is where all the work we've already done matters.

We now know not to blindly create abstractions whenever structure appears.

A proposed new way of seeing things has to beat:

[
\texttt{KEEP}
]

and:

[
\texttt{COMPRESS}
]

and existing compositions.

A proposed primitive has to demonstrate:

[
\text{functional substitutability}.
]

A proposed schema has to beat:

[
\text{matched-budget private encoding}.
]

A retained concept has to repay its prospective cost.

And, after V4, we know decisions can interact through future library evolution.

So eventually the outer loop is not merely compression:

[
\boxed{
\textbf{it is planning over changes to the model's own language.}
}
]

That's a very unusual destination.

## I think the grand hypothesis has crystallized further

Previously we had:

[
\boxed{
\text{Intelligence progressively moves recurring information into representations where future reuse is cheapest.}
}
]

I would now expand it:

[
\boxed{
\begin{aligned}
\textbf{Intelligence may consist in continually searching for}\\
\textbf{programs that explain and control experience, while}\\
\textbf{continually inventing representations and primitives}\\
\textbf{that make future program search cheaper.}
\end{aligned}}
]

Or even more compactly:

[
\boxed{
\textbf{Reasoning searches within a language;
learning improves the search;
abstraction improves the language.}
}
]

And dreaming/theorizing is what allows programs in that language to be **executed as hypotheses before reality settles the question**.

If we can demonstrate that loop experimentally—not metaphorically—I think that's the road from the relatively modest V1–V4 results to the much larger thing you're imagining.
