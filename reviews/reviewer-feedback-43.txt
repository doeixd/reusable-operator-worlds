That's good.

\boxed{
\text{The representation chosen by the learner changes predictably with the economics of reuse.}

Not just one crossover.

Something like:

That would be a much bigger result than another mechanism winning.

# V5.1: Make the amortization law genuinely causal

The current sketch already recognizes the problem: recomputing

[
H^*=\frac{\lambda D(A)}{\bar{s}}
]

with a different accounting scheme isn't an empirical test. So V5.1 manipulates the underlying quantities instead.

I think this is exactly right.

The experiment I would want is:

[
D(A)\uparrow \quad\Rightarrow\quad H^*\uparrow
]

and independently:

[
\bar{s}\uparrow \quad\Rightarrow\quad H^*\downarrow.
]

Then ideally:

[
H^*\bar{s}\approx\lambda D(A)
]

across the whole grid.

### The major danger

Changing residual **rank** doesn't only change description length.

It can also change:

* functional complexity,
* trainability,
* approximation quality,
* reacquisition speed,
* magnitude of improvement,
* optimization geometry.

So rank isn't a pure intervention on (D).

The current sketch partially handles this correctly by saying the actual law should be tested as

[
H^*\bar{s}\propto D
]

rather than assuming (\bar{s}) stays fixed.

I would go further and make this a core diagnostic.

For every rank arm separately measure:

[
D^*(A),\quad \bar{s},\quad C_{\text{reacquire}}
]

before looking at the crossing.

Then predict the crossing.

Do **not** fit the crossing and subsequently explain it using those quantities.

That's the difference between a law and curve-fitting.

# V5.2: I would make the “second representation class” categorical

This is where I think you can substantially improve the current plan.

V4R found that factorization didn't pay: independently compressed abstractions were cheaper.

The current V5 plan proposes creating a world with enough **meta-recurrence** that factorization can genuinely become economical.

Good.

But I wouldn't make the meta-recurrence arbitrary.

I would create the following world.

There is some latent reusable computation:

[
A:X\rightarrow Y.
]

But every family sees it through a different representation:

[
f_i
===

d_i\circ A\circ e_i.
]

So:

```text
     e₁          A          d₁
X₁ ───→ X ───────────→ Y ───→ Y₁

     e₂          A          d₂
X₂ ───→ X ───────────→ Y ───→ Y₂

     e₃          A          d₃
X₃ ───→ X ───────────→ Y ───→ Y₃
```

Now compare:

[
R_1={f_1,f_2,\ldots,f_n}
]

against:

[
R_2={A,e_1,d_1,e_2,d_2,\ldots}.
]

The MDL decision is:

[
D(A)+\sum_i[D(e_i)+D(d_i)]
\overset{?}{<}
\sum_iD(f_i).
]

This is **exactly** the issue you expect to encounter in LLMs.

The same abstract computation probably doesn't appear at layer 8 and layer 26 operating in identical coordinates.

It might instead be:

> the same morphism expressed in two different internal representational systems.

That gives category theory a real job.

The experiment asks whether a commuting diagram exists cheaply enough to be worth representing.

# Why that V5 experiment could be very important

You could sweep the cost of the adapters.

At one extreme:

[
e_i,d_i\approx I.
]

Then exact sharing should win.

As adapters become more complicated:

[
D(e_i)+D(d_i)\uparrow
]

there should eventually be a crossover where maintaining independent implementations becomes cheaper.

So you'd get:

[
\text{exact sharing}
\rightarrow
\text{shared abstraction + adapters}
\rightarrow
\text{independent implementations}.
]

That's a **representation phase transition**.

And suddenly your project is studying exactly the distinction that matters to your duplicate-circuit hypothesis:

> When are two different neural circuits economically better understood as implementations of the same abstract computation?

That is much deeper than parameter clustering.

# V5.3: Require factorization to predict something it hasn't seen

This should be non-negotiable.

Suppose you discover:

[
f_1=d_1Ae_1,\quad
f_2=d_2Ae_2,\quad
f_3=d_3Ae_3.
]

It is easy to create some representation that compresses those three retrospectively.

The real test is:

> Does (A) help with (f_4)?

So hold out an entire family member.

Learn the core from:

[
f_1,f_2,f_3.
]

Then on (f_4), allow learning only the adapters:

[
e_4,d_4.
]

Compare that against learning (f_4) independently.

If:

[
L_{\text{learn adapters}}
<
L_{\text{learn whole }f_4},
]

you've discovered something genuinely reusable.

That's analogous to V3's distinction between compression of the past and prospective abstraction.

I'd call this **meta-transfer**.

# V5.4: Can one score actually choose the representation?

This is the really important culmination of V5.

Don't tell the learner which world it is in.

Sometimes generate:

```text
unrelated computations
```

sometimes:

```text
weak recurrence
```

sometimes:

```text
same abstract computation
+ expensive adapters
```

sometimes:

```text
same computation
+ cheap adapters
```

sometimes:

```text
exact recurrence
```

And allow:

[
{\text{KEEP PRIVATE},
\text{COMPRESS},
\text{FACTORIZE},
\text{SHARE}}.
]

Then compare the learner's predicted choice with an oracle that can evaluate the actual remaining lifetime.

The important metric isn't simply classification accuracy.

Use **regret**:

[
\operatorname{Regret}
=====================

## J(\text{chosen representation})

\min_R J(R).
]

Then you can ask whether estimated value is calibrated:

[
\hat V(R)\approx V_{\text{actual}}(R).
]

That gets you toward something extremely important:

> the learner doesn't merely possess abstraction mechanisms; it knows when to use them.

The current V5 plan already moves toward structural regret and a prospective score.  I think that's the right endpoint.

# V5.5: The open-library problem

This is where things become sequential.

The current sketch recognizes that once the library can change, an abstraction's value isn't independent anymore. Deleting (A) might cause (A') to be rediscovered, so the apparent storage saving disappears.

Now you're no longer solving:

[
\arg\min_R J(R).
]

You're solving:

[
\pi^*
=====

\arg\min_\pi
E\left[
\sum_t
J(R_t,a_t)
\right].
]

This is where I'd introduce **short counterfactual rollouts** before trying to learn a policy.

For each candidate edit:

```text
KEEP
DELETE
COMPRESS
FACTORIZE
```

clone the learner and simulate perhaps the next (k) tasks.

Then compare:

[
Q_k(R,a)
========

C(a)+
\sum_{i=1}^{k}J_{t+i}.
]

If even a short rollout beats a myopic score substantially, you've demonstrated that **representation management is genuinely a planning problem**.

That's already beginning to touch the reasoning/planning theme without anthropomorphizing it.

The learner is literally hypothesizing:

> “What happens if I rewrite my representation this way?”

and rolling that representation forward.

# One issue I would take especially seriously: functional equivalence can lie

This matters for the category-theoretic direction.

There's existing work showing that simple model-stitching success is not sufficient evidence that two representations contain the same information: surprisingly different or even pathological representations can sometimes be stitched successfully. ([Proceedings of Machine Learning Research][1])

So don't define:

[
f\sim g
]

merely because some powerful learned adapter makes them interchangeable.

A sufficiently expressive adapter could itself implement all the computation.

Your test needs an **adapter complexity budget**.

For example:

[
f\sim g
]

only when there exist cheap (a,b) such that:

[
b\circ f
\approx
g\circ a
]

on proposal data **and disjoint validation interventions**, while:

[
D(a)+D(b)\ll D(f),D(g).
]

Otherwise you've merely hidden the computation in the adapters.

This is potentially one of the most important methodological rules for later LLM experiments.

f:X\to Y.

and:

[
g\circ f.

Before products.

Before branches.

Before loops.

Before recursion.

The first V6 question should simply be:

## V6.1: Held-out composition

Suppose the library has discovered:

[
A,B,C,D,E.
]

Training tasks contain combinations like:

[
B\circ A
]

[
D\circ B
]

[
C\circ A
]

but never:

[
D\circ C\circ A.
]

Then test whether the learner can assemble:

[
D\circ C\circ A
]

with little or no parameter learning.

That's the first real compositional-generalization result.

And depth should matter.

Train on programs of length:

[
1,2,3
]

and test:

[
4,5,6,8.
]

If execution remains correct as depth grows, you've separated:

[
\text{knowing primitives}
]

from:

[
\text{having memorized combinations}.
]

The current V5 sketch already mentions an operational compositional-closure probe at depth 8.  I think that probe should become the **entry criterion for V6**.

# V6.2: Programs should become primitives

This is the experiment I consider central to your ultimate thesis.

Suppose:

[
C\circ B\circ A
]

keeps appearing.

The learner initially executes:

```text
CALL A
CALL B
CALL C
```

Eventually it should ask whether to create:

[
M=C\circ B\circ A.
]

Then future programs can say:

```text
CALL M
```

instead.

The economic condition becomes something like:

[
D(M)
+
N,D(\operatorname{CALL}M)
+
C_{\text{creation}}
<
N[D(A)+D(B)+D(C)]
]

while also considering execution/search costs.

And then the crucial part:

[
M
]

must itself be composable:

[
E\circ M\circ D.
]

Now you have:

[
\text{program}
\rightarrow
\text{abstraction}
\rightarrow
\text{primitive}
\rightarrow
\text{larger program}.
]

That is the beginning of **recursive abstraction**.

# V6.3: Category laws can stop the library exploding

Suppose the learner represents:

[
(C\circ B)\circ A
]

and separately:

[
C\circ(B\circ A).
]

These aren't two programs.

Associativity says:

[
(C\circ B)\circ A
=================

C\circ(B\circ A).
]

Similarly:

[
f\circ \operatorname{id}=f.
]

This matters computationally.

Without canonicalization, the learner's library can accumulate enormous numbers of syntactically different expressions representing the same computation.

Category theory therefore gives you a **quotient over program syntax**.

Instead of storing syntax trees literally, normalize modulo laws such as:

[
(f\circ g)\circ h
\equiv
f\circ(g\circ h).
]

That could make search and MDL substantially cleaner.

This is one place where category theory isn't decoration at all—it tells you which distinctions the learner should *not pay bits for*.

---

# V6.4: Types should eventually constrain search

If every module is:

[
\mathbb R^{16}\rightarrow\mathbb R^{16},
]

then everything technically composes with everything.

As the library grows:

[
K^L
]

candidate programs become impossible to search.

Eventually you need interfaces like:

[
A:X\rightarrow Y
]

[
B:Y\rightarrow Z
]

while:

[
C:Q\rightarrow R
]

can't follow (A).

HOUDINI is relevant prior art here: it represents differentiable neural programs in a strongly typed functional language and found that type-directed search substantially reduces the search problem. ([Google Research][2])

But I wouldn't have ROW **learn the types immediately**.

First:

```text
V6a: known types
V6b: inferred types
```

Otherwise if something fails you won't know whether:

* composition failed,
* program search failed,
* type induction failed,
* or the neural primitives failed.

Keep those hypotheses separable.

---

# V6.5: Only then add richer categorical structure

Once sequential composition works, then introduce things like parallel composition / multiple inputs.

That's where symmetric monoidal structure starts becoming relevant.

Later:

```text
COPY
PAIR
SELECT
CASE
```

and eventually:

```text
LOOP / TRACE
```

But I would make each new structural primitive earn its place exactly the way ROW has made abstractions earn theirs.

Don't assume branches are useful.

Create an opportunity census.

Ask an oracle:

[
\text{Would BRANCH reduce lifetime cost here?}
]

If no, don't build it.

That's one of the most valuable lessons V4 gave you.

# The three experiments I would be most excited about

If I had to prioritize the whole roadmap, I'd choose these:

| Experiment                                               | Why it matters                                                                                                     |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| **Causal amortization law**                              | Establishes that the economics actually predict interventions rather than redescribe outcomes                      |
| **Same morphism under different coordinates**            | Connects ROW directly to your duplicated/entangled-circuit hypothesis and gives category theory a substantive role |
| **Repeated composition → new primitive → recomposition** | Demonstrates the recursive abstraction mechanism needed for a genuinely growing computational language             |

If all three worked, the story would become much stronger:

[
\boxed{
\text{repeated computation}
\rightarrow
\text{shared morphism}
\rightarrow
\text{economically selected abstraction}
\rightarrow
\text{composition}
\rightarrow
\text{repeated composition}
\rightarrow
\text{new morphism}.
}
]

At that point, I think you'd have experimentally instantiated a surprisingly large piece of your original intuition.

The most important thing is not to rush from ROW to an LLM. **V5 should establish the economics as predictive; V6 should establish recursive compositional abstraction as real.** If those succeed, then V7/V8 can ask the much more consequential question: whether a learner whose language itself improves can solve increasingly novel programs—and whether that mechanism gives you a different, more efficient route to scaling than simply making a dense model larger.
