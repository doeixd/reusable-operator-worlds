Yes. **I think you’re right.** The result we’re currently excited about is, at a high level, almost what information theory says *should* happen.

The key insight is that **reuse is compression**.

Suppose we have tasks (T_1,\ldots,T_N). If you learn each independently, the description cost is roughly

[
L_{\text{independent}}
\approx
\sum_{i=1}^{N} K(T_i).
]

But suppose they are generated from a common computational library (P), plus a short task-specific program (r_i):

[
T_i=P(r_i).
]

Then you can encode the whole family as

[
L_{\text{shared}}
\approx
K(P)+\sum_{i=1}^{N}K(r_i\mid P).
]

The library is paid for **once**.

Everything afterward only has to specify what's different.

That's exactly the mechanism we've been observing experimentally.

## The Shannon version makes it even clearer

Imagine all tasks share some latent variable (Z)—in ROW, roughly the reusable operator library.

Without exploiting (Z):

[
L_{\text{independent}}\approx\sum_i H(T_i).
]

If we first encode (Z):

[
L_{\text{shared}}
\approx
H(Z)+\sum_iH(T_i\mid Z).
]

Since

[
H(T_i)-H(T_i\mid Z)=I(T_i;Z),
]

the savings are approximately

[
\boxed{
\sum_iI(T_i;Z)-H(Z).
}
]

That's basically the entire story.

There's an **up-front cost** to learning/storing the reusable representation:

[
H(Z).
]

But every new related task gives you a benefit:

[
I(T_i;Z).
]

Once:

[
\sum_iI(T_i;Z)>H(Z),
]

the abstraction has paid for itself.

And after that, each additional related task is cheaper.

### Which predicts exactly our (\rho) result

At:

[
\rho=0,
]

there's essentially no common computational information:

[
I(T_i;Z)\approx0.
]

So maintaining a shared basis is pointless—or actively harmful because you're imposing the wrong bottleneck.

At:

[
\rho=1,
]

there is lots of common information.

So paying once for:

[
P_1,\ldots,P_6
]

and then merely learning:

[
[P_2,P_5,P_1]
]

for each task should beat relearning its transformation from scratch.

So yes:

[
\boxed{
\rho\uparrow
\Rightarrow
\text{shared information}\uparrow
\Rightarrow
\text{value of reuse}\uparrow
}
]

is almost an information-theoretic prediction.

And there is already formal transfer-learning theory in essentially this spirit: if tasks share a latent representation, learning that representation across source tasks can reduce the number of samples needed on new tasks. ([arXiv][1]) MDL-control goes even closer: it explicitly learns common structure across tasks, compresses it into a simpler shared representation, and uses that representation to obtain faster learning/generalization on subsequent tasks. ([arXiv][2])

So **that cannot be the ultimate novelty of our project.**

## But this realization is useful, because it tells us what the interesting question actually is

Information theory says:

> If I give you the correct shared latent code (Z), exploiting it should save information.

It does **not** tell us:

> How does a general neural learner discover what (Z) should be?

That's considerably harder.

Consider a large set of tasks whose shortest joint description is:

```text
A
B
C
D

program 1: A B D
program 2: A C D
program 3: B C A
...
```

We know *after the fact* that this is compressed.

But SGD doesn't receive:

```text
Here are A, B, C, and D.
```

It receives millions of:

[
(x,y)
]

pairs.

So the interesting problem is:

[
\boxed{
\text{Can learning dynamics discover the factorization that approaches the joint compression bound?}
}
]

That's not trivial.

That starts becoming interesting.

And here's the version that I think remains genuinely exciting:

> **Can the learner modify the language in which it learns so that it approaches the compression structure of its environment over time?**

Meaning it can decide:

[
\text{reuse}

vs.

[
\text{specialize}

vs.

[
\text{fork}

[
\text{merge}

# This connects beautifully to the scaling question

Our original intuition about LLMs can be restated in information-theoretic terms.

Suppose the behavior of a trillion-parameter model contains many tasks/functions:

[
T_1,\ldots,T_N.
]

The naive architectural representation might effectively cost something approaching:

[
\sum_iK(T_i).
]

But perhaps their true joint complexity is closer to:

[
\boxed{
K(P)+\sum_iK(r_i\mid P)
}
]

where (P) is a relatively small reusable computational language.

Then the billion/trillion parameters aren't necessarily reflecting the **intrinsic information content** of the model's competencies.

They may partly reflect an architecture that has found a relatively inefficient representation of their **joint structure**.

That's exactly analogous to compression.

---

## A simple example

Imagine 1,000 functions all independently contain an FFT implementation.

Naively:

[
1000\times K(\mathrm{FFT}).
]

With functions:

```text
FFT = ...

function_1:
    FFT(...)
    ...

function_2:
    FFT(...)
    ...
```

you pay:

[
K(\mathrm{FFT})
]

once.

That's obvious.

What's not obvious is whether a neural network trained only from behavioral examples will spontaneously discover:

> **“Hey, these apparently different computations contain the same algorithm. I should represent that algorithm once.”**

That's much closer to our actual question.

# And this gives us a theoretical prediction for the (\rho) experiment

The crossover isn't just something we hope to observe.

There should be an economic threshold.

Suppose a reusable primitive costs:

[
C_P
]

bits to learn/store.

And each related task saves approximately:

[
s(\rho)
]

bits by using it.

After (N) tasks, sharing wins when:

[
N s(\rho)>C_P.
]

Therefore:

[
N^*(\rho)
\approx
\frac{C_P}{s(\rho)}.
]

That's neat.

At high reuse:

[
s(\rho)\gg0
]

so:

[
N^*
]

is small.

The abstraction pays for itself quickly.

At low reuse:

[
s(\rho)\rightarrow0
]

so:

[
N^*\rightarrow\infty.
]

**Never bother abstracting.**

That predicts not just a (\rho) threshold, but a relationship between:

[
\boxed{
\text{reuse strength}
\times
\text{number of experiences}
\times
\text{primitive complexity}.
}
]

This actually gives us a much richer synthetic experiment later.

## So I would slightly change what we're aiming for

The theoretical north star becomes:

[
\boxed{
\textbf{Can a neural learner approach the joint description length of its lifetime experience by inventing its own reusable computational representation?}
}
]

Or even:

> **Can neural learning discover algorithmic mutual information between tasks and turn it into reusable computation?**

That's a much sharper statement.

The interesting territory is the **algorithm for discovering the code**.

And then our original LLM hypothesis becomes:

> Large dense Transformers may be solving a joint-compression problem badly: SGD discovers enormous amounts of shared algorithmic structure, but the architecture may lack mechanisms to factor that structure into a compact callable computational library.

**That** I still think is a really interesting thing to investigate.

So your instinct here is right: **the current headline statement is almost too obvious. We should treat it as the foundation/theoretical expectation, not as the eventual contribution.**
