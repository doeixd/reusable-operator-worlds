# Should the basis be frozen during Phase B?

There are two versions.

### Clean mechanism demonstration

Freeze the six existing shared operators while new family structure accumulates.

Tasks can adapt only through residuals.

Then at sleep:

[
\operatorname{PROMOTE}
]

is allowed to create slot 7.

This is somewhat artificial, but **extremely interpretable**.

It directly tests:

[
\text{repeated local computation}
\rightarrow
\text{new shared object}.
]

For V3's first demonstration, I think this is defensible.

### Harder natural version

Let the six existing shared operators continue learning.

But preserve old-task behavior.

Now repurposing an existing operator causes interference:

[
P_j\rightarrow P'_j
]

may improve new families while damaging old programs.

PROMOTE offers another option:

[
P_7=\text{new abstraction}
]

without overwriting old shared structure.

This version is much closer to continual learning and naturally leads into V4's copy-on-write/FORK story.

I'd probably do the clean version first and the natural version as the robustness test.

### One additional shared operator

[
D_{\rm task}\downarrow

[
D(P_{K+1})+D(\text{references}).

Then you know there's actually something for PROMOTE to discover.

This is the V3 analogue of validating that V1's teacher structure exists before testing learners.

# This also changes how I think about PROMOTE

Originally PROMOTE was:

Now I think the deeper operation is:

[
\boxed{
\operatorname{PROMOTE}

Residual factorization is merely one way to propose the candidate.

The actual structural event is:

[
\text{private computational capacity}
\rightarrow

That generalizes much better.

At scale, promotion might mean:

* create a new operator;

* create a parameterized family;
* create a macro;

The invariant is **migration of repeated private information into a shared addressable representation**.

# And this tells us something important about the grand architecture

Your current learner had:

[
\text{free shared capacity}.
]

It used it.

That's exactly what a rational architecture should do.

So perhaps structural learning eventually consists of two levels:

### Cheap inner adaptation

If existing capacity can express the recurrence:

[
\boxed{\text{reorganize what already exists}.}
]

No library growth required.

### Expensive outer restructuring

Only when existing capacity cannot encode the recurring structure economically:

[
\boxed{\text{grow/restructure the language}.}
]

That gives PROMOTE a much more principled role.

It shouldn't fire whenever recurrence exists.

It should fire when:

[
\boxed{
\text{recurrence exists}
+
\text{existing representational capacity cannot absorb it economically}.
}
]

That's a better theory.
