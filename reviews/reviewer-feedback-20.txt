# One more conceptual point: your empirical-Bayes prior may become less important

The Gaussian approach needed to answer:

> What width should the null prior have?

That's inherently awkward because:

* wide prior = cheap large deviations but noisy null;
* narrow prior = quiet null but expensive deviations.

The presence representation removes that conflict.

Null is:

[
g=0.
]

The slab distribution only matters **conditional on (g=1)**.

So you can estimate:

[
p(v\mid g=1)
]

from actual innovations without simultaneously asking it to represent “no innovation.”

That is a much better statistical factorization.

I suspect this will eliminate several of the pathological prior-scale behaviors the agent just fought through.

I would elevate this to a principle alongside the identity-state rule:

[
\boxed{
\textbf{Different semantic kinds of task information need different codes.}
}

[
q(\text{all task state})
\sim\mathcal N(0,\sigma^2).

You want something more like:

[
\boxed{

\quad|\quad
\text{INNOVATION}
\quad|\quad

### Reference

Potentially expensive.

This is already starting to look like the calling convention of a learned language.
