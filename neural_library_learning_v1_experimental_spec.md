# Neural Library Learning
## V1 Experimental Specification: Reusable Operator Worlds

**Status:** implementation-ready research specification  
**Date:** August 17, 2026  
**Project:** Neural Library Learning / Prospective Neural Compression

## 0. Core goal

Test whether a learner can become progressively more sample-efficient by accumulating and reusing computational structure, rather than merely accumulating task-specific parameters.

The first experiment should **not** attempt to decompile an LLM, train a dynamic neural compiler, or implement genetic restructuring.

It should answer:

> **When a learner experiences a lifetime of tasks generated by reusable hidden computations, does giving it a reusable computational substrate cause later tasks to become cheaper to learn?**

The benchmark should make this falsifiable by ensuring:

1. hidden reusable computations are known to us but not to the learner;
2. hidden computations are randomly generated rather than human-named functions;
3. tasks have matched compositional depth and approximately matched intrinsic difficulty;
4. we can vary how much genuine reusable structure exists;
5. later tasks are not intrinsically easier;
6. an oracle demonstrates that reuse can help;
7. a continuous-basis baseline tests whether discrete/dynamic abstraction is unnecessary;
8. the headline metric is **lifetime/prequential learning cost**, not final accuracy.

Call the benchmark **Reusable Operator Worlds (ROW)**.

---

# 1. Hypotheses

## H0 — Null

Given sufficient ordinary shared capacity, standard gradient-based learners extract all practically useful reusable computation from compositionally related tasks. Explicit libraries, routing, MDL pressure, or structural refactoring provide no meaningful improvement at matched compute and retained complexity.

## H1 — Reusable-computation hypothesis

A learner with an architectural substrate that permits explicit reuse of learned transformations will require fewer examples to learn later tasks when those tasks share latent computational structure with earlier tasks.

Let \(N_n\) be examples required to reach a fixed performance threshold on task \(T_n\). We predict a stronger decline in \(N_n\) over lifetime experience for reusable learners than for dense learners.

## H2 — Structure-dependence hypothesis

Let \(ho\in[0,1]\) control how similar/reusable latent operations are across tasks. We predict:

\[
\frac{\partial}{\partial \rho}
\left(
L_{\mathrm{preq,dense}}
-
L_{\mathrm{preq,reuse}}
\right) > 0.
\]

At low \(ho\), aggressive sharing should provide little benefit or hurt. At high \(ho\), reuse should increasingly reduce lifetime learning cost.

## H3 — Abstraction-quality hypothesis

If reuse explains the gain, learned operations should have a compact functional correspondence with recurring hidden computations, even if the learner discovers a different basis from the teacher.

## H4 — Strong self-refactoring hypothesis

A dynamic learner that can fork, specialize, merge, and consolidate computations will outperform a fixed overcomplete basis when reuse structure varies over the lifetime.

**This is not required for V1.**

---

# 2. Main falsifiers

The project should stop or change direction if:

- a dense model matches reusable models on prequential loss, examples-to-criterion, and retained complexity in high-reuse worlds;
- a simple continuous shared basis matches or beats discrete/dynamic systems;
- reusable systems appear to improve over lifetime at \(ho=0\), suggesting leakage or a benchmark confound;
- the oracle compositor does not gain substantial sample efficiency in high-reuse worlds;
- dynamic models only win because they use materially more parameters, FLOPs, updates, replay, or task-specific state.

A null result is useful if the benchmark and positive controls work.

---

# 3. Why random neural operators instead of a hand-written DSL?

A hand-written DSL such as `REVERSE`, `FILTER`, `COPY`, or `COMPARE` is intuitive, but it introduces unnecessary ambiguity:

- different primitives may have different intrinsic difficulty;
- some compositions simplify algebraically;
- the learner may find a better basis than our semantic vocabulary;
- the architecture may accidentally be tailored to our chosen functions;
- semantic names encourage over-interpretation.

For V1, generate the true operations randomly from one neural function family.

This gives us:

- matched primitive complexity;
- exact causal structure;
- cheap data generation;
- no semantic assumptions;
- an objective reuse parameter;
- clean functional-equivalence testing.

A symbolic DSL can be a later interpretability benchmark.

---

# 4. ROW world generator

Each world \(W\) contains hidden transformations:

\[
\mathcal P^W=\{P_1,\dots,P_K\}.
\]

A task is a hidden program:

\[
\pi_\tau=(i_1,\dots,i_L)
\]

which defines:

\[
f_\tau(x)
=
P_{i_L}\circ\cdots\circ P_{i_1}(x).
\]

The learner sees only:

- an arbitrary task ID;
- an input \(x\);
- a target \(y=f_\tau(x)\).

It never receives the hidden route.

---

# 5. Ground-truth primitive construction

Start with:

\[
x\in\mathbb R^{16},\qquad x\sim\mathcal N(0,I).
\]

Each hidden primitive is:

\[
P_k(z)=
\tanh\left(
z+
\alpha U_k\tanh(V_kz+b_k)
\right).
\]

Initial values:

- state dimension \(d=16\);
- bottleneck rank \(r=8\);
- \(V_k\in\mathbb R^{8\times16}\);
- \(U_k\in\mathbb R^{16\times8}\);
- \(b_k\in\mathbb R^8\);
- residual scale \(lpha=0.35\).

Sample weights from a fixed random distribution and normalize matrix norms so primitive scale is comparable.

The outer `tanh` bounds repeated composition.

Start with:

\[
K=6,\qquad L=3.
\]

There are \(6^3=216\) possible ordered programs—enough for dozens of unique tasks.

---

# 6. Task construction

For V1 every task uses exactly three primitive calls.

Example hidden program:

```text
P4 -> P1 -> P6
```

The learner sees:

```text
task_id = random_37
x -> y
```

Task IDs are randomly permuted after program generation and contain zero information about route structure.

Do not repeat identical full programs in the primary lifetime stream. We want transfer from reusable constituents, not memorization of whole tasks.

---

# 7. Benchmark A — exact reuse

This is the first benchmark.

Every task is composed from the same hidden library:

\[
\{P_1,\dots,P_6\}.
\]

Thus:

\[
\rho=1.
\]

This intentionally creates a world where computational reuse should be extremely valuable.

If a reusable learner cannot exploit this, do **not** build a dynamic compiler yet.

---

# 8. Benchmark B — a continuum of reuse

After Benchmark A works, create a smooth reuse parameter.

For each base primitive parameter vector/tensor \(	heta_k\), sample independent task-specific perturbations \(\epsilon_{\tau,k}\) and define:

\[
\theta_{\tau,k}
=
\rho\theta_k
+
\sqrt{1-\rho^2}\epsilon_{\tau,k}.
\]

Normalize corresponding matrices to keep operation scale stable.

Interpretation:

- \(ho=1\): exact same operation across tasks;
- \(ho\approx0.75\): strong common computation plus specialization;
- \(ho\approx0.5\): moderate common structure;
- \(ho\approx0\): operator identity no longer corresponds to the same function.

Sweep:

\[
\rho\in\{0,0.25,0.5,0.75,0.9,1.0\}.
\]

Because parameter correlation is only a proxy for functional similarity, also estimate actual functional similarity on probe inputs.

This benchmark asks:

> **At what degree of latent recurrence does sharing become economical?**

---

# 9. Benchmark C — prospective macro structure

Only after A/B work.

Introduce reusable macros such as:

\[
M_A=[P_2,P_5],\qquad M_B=[P_1,P_4].
\]

Use a hidden Markov regime:

\[
r_t\in\{A,B\},\qquad P(r_{t+1}=r_t)=0.9,
\]

where regime \(A\) favors tasks containing \(M_A\) and regime \(B\) favors \(M_B\).

This makes future reuse predictable from the task-generating process and distinguishes:

- compressing what happened in the past;
- inventing abstractions that are likely to pay off in the future.

Relevant work: **Prospective Compression in Human Abstraction Learning**  
https://arxiv.org/abs/2605.09985

Do not put this complexity into V1.

# 10. Lifetime

Initial lifetime:

- 64 tasks;
- 128 online training examples per task;
- 256 fixed evaluation examples per task;
- program length 3.

Total stream:

\[
64\times128=8192
\]

online examples per world.

Evaluate each task after:

\[
n\in\{0,1,2,4,8,16,32,64,128\}
\]

examples.

Generate the entire task set before training and evaluate both a random order and the reverse order to detect curriculum effects.

prediction = model(task_id, x)

# 12. Model 0 — oracle compositor

Positive control.

The oracle receives the true hidden route \((i_1,i_2,i_3)\) and has six learned operator slots.

It still must learn what each hidden operation does.

Once the operations are learned, novel compositions should become nearly zero/few-shot.

If the oracle does not improve substantially over lifetime, the benchmark is not useful enough.

---

# 13. Model 1 — dense baseline

Input:

\[
[x,e_\tau]
\]

where \(e_\tau\) is a learned task embedding.

Suggested initial architecture:

- task embedding: 32 dims;
- hidden width: 128;
- 3 residual MLP blocks;
- GELU or tanh;
- output dimension 16.

Train both task embedding and shared network online.

Use at least:

- **Dense-P:** approximately parameter-matched;
- **Dense-C:** approximately compute-matched.

Do not depend on one arbitrary dense baseline size.

---

# 14. Model 2 — fixed discrete reusable library

Give the learner an overcomplete library:

\[
Q_1,\dots,Q_{12}
\]

even though the teacher has six primitives.

Each task gets three route variables:

\[
q_{\tau,1},q_{\tau,2},q_{\tau,3}.
\]

Computation:

\[
z_0=x
\]

\[
z_1=Q_{q_{\tau,1}}(z_0)
\]

\[
z_2=Q_{q_{\tau,2}}(z_1)
\]

\[
z_3=Q_{q_{\tau,3}}(z_2).
\]

**Critical bottleneck:** task ID is not fed into the operators. It influences computation only through route selection.

This prevents a single giant operator from secretly conditioning on task identity.

Train route logits using Gumbel-softmax or another relaxed categorical method, annealing toward hard routing.

Always evaluate the final model with hard routes.

A hardened task program costs only about:

\[
3\log_2(12)\approx10.8
\]

bits before coding overhead.

---

# 15. Model 3 — fixed continuous operation basis

This is probably the strongest conceptual baseline.

Instead of choosing one discrete operator:

\[
Q_i,
\]

construct:

\[
Q_\alpha(z)
=
\sum_{i=1}^{B}\alpha_iQ_i(z)
\]

or later mix low-rank operator parameters.

Start with:

\[
B=8.
\]

Each task step gets a low-dimensional coefficient vector.

This directly tests the possibility that the optimal reusable computational language is **continuous** rather than a set of function-like modules.

Relevant work: **Attention as a Hypernetwork**  
https://arxiv.org/abs/2406.05816

That work finds low-dimensional latent codes specifying reusable operations in attention and motivates taking this baseline seriously.

If this simple model wins, abandon unnecessary discrete compiler machinery.

---

# 16. Model 4 — MDL-pruned overcomplete library

Only after Model 2 works.

Start with 12 operator slots and attach learnable presence gates \(g_i\).

Train with a surrogate objective:

\[
L=
L_{\mathrm{predict}}
+
\lambda_{\mathrm{lib}}
\sum_i\mathbb E[g_i]
+
\lambda_{\mathrm{route}}L_{\mathrm{route}}.
\]

Use an \(L_0\)/hard-concrete-style gate or similarly explicit mechanism.

Question:

> Does a world generated from six reusable operations cause an overcomplete library to settle on a substantially shorter sufficient computational basis?

Do **not** require exactly six learned operators. Another basis may be equally or more compact.

---

# 17. Model 5 — shared parent + residual

For intermediate \(ho\), first test the copy-on-write idea **without dynamic topology**.

At step \(l\):

\[
Q_{\tau,l}(z)
=
Q_{q_{\tau,l}}(z)
+
R_{\tau,l}(z)
\]

where \(R_{\tau,l}\) is a small low-rank residual with an explicit storage penalty.

Prediction:

- at high \(ho\), residuals should approach zero;
- at low \(ho\), residuals should carry more information.

This gives a graded sharing baseline before merge/split logic.

---

# 18. Model 6 — dynamic structural learner

Phase II only.

Represent a child as:

\[
Q_{\text{child}}
=
Q_{\text{parent}}+\Delta,
\qquad \Delta_0=0.
\]

The cheapest adaptation hierarchy becomes:

1. reuse exactly;
2. reuse with a small residual;
3. fork into a distinct operation.

Start dynamic actions with only:

```text
FORK
MERGE
DELETE
```

Later:

```text
PROMOTE_RESIDUAL
EXTRACT_MACRO
INLINE_MACRO
```

A genetic/meta-learned structural optimizer is much later.

---

# 19. Lifetime/prequential objective

Let \(M_t\) be the learner **before** receiving example \(t\).

Primary predictive metric:

\[
L_{\mathrm{preq}}
=
\sum_{t=1}^T
-\log
p_{M_{t-1}}(y_t\mid x_t,\tau_t).
\]

This is the correct direction because it rewards a learner that becomes able to predict future data from fewer examples.

Relevant work: **Sequential Learning Of Neural Networks for Prequential MDL**  
https://arxiv.org/abs/2210.07931

For continuous targets, use a fixed Gaussian likelihood:

\[
p(y\mid x)
=
\mathcal N(\hat y,\sigma^2I)
\]

with fixed \(\sigma\), initially 0.1.

Do not let a model reduce apparent NLL by learning inflated uncertainty.

---

# 20. Full later objective

The eventual self-refactoring learner should be evaluated on:

\[
J=
L_{\mathrm{preq}}
+
\lambda D(M_T)
+
\mu C_{\mathrm{train+infer}}
+
\nu P_{\mathrm{peak}}.
\]

Where:

- \(D(M_T)\): retained model/program description length;
- \(C\): compute;
- \(P_{\mathrm{peak}}\): peak temporary search capacity.

This permits useful overparameterization during learning without allowing unlimited free scratch space.

Do not charge full library size at every time step; prequential loss already measures whether early abstractions made later data cheaper.

---

# 21. Online training protocol

For each task:

1. initialize task-specific state identically by policy;
2. evaluate zero-shot performance;
3. stream examples;
4. **predict before updating** and record prequential loss;
5. update current task state and shared parameters;
6. train with a matched replay minibatch;
7. evaluate at the predefined support counts;
8. move to next task.

Suggested initial optimizer:

- AdamW;
- global LR \(10^{-3}\);
- task-code LR \(5\times10^{-3}\);
- weight decay \(10^{-4}\);
- batch size 8.

Keep optimization boring until the benchmark is stable.

---

# 22. Replay

Use matched replay so the main effect is not simply “modularity forgets less.”

Initial buffer:

- 4 examples per completed task;
- cap at 256 using reservoir sampling;
- current:replay minibatch ratio 1:1.

Later ablate:

- no replay;
- 1:4;
- 1:1.

If the advantage disappears with strong replay, then the result may mostly concern catastrophic forgetting rather than forward transfer.

---

# 23. Primary metric 1 — cumulative prequential loss

For every model/world plot:

\[
L_{\mathrm{preq}}(t).
\]

This is the cleanest lifetime metric.

The reusable learner should accumulate fewer predictive bits if previous learning makes future examples easier to encode.

---

# 24. Primary metric 2 — examples-to-criterion

Define normalized MSE:

\[
\operatorname{NMSE}
=
\frac{
\mathbb E\|y-\hat y\|^2
}{
\mathbb E\|y-\bar y\|^2
}.
\]

For each task:

\[
N_\tau
=
\min\{n:\operatorname{NMSE}_{\tau,n}<\epsilon\}.
\]

Start with:

\[
\epsilon=0.05
\]

and report sensitivity at 0.10 and 0.02.

If threshold is not reached by 128 examples, treat as right-censored or use 129 for simple plots.

**Headline plot:**

\[
N_\tau
\quad\text{vs.}\quad
\text{task index}.
\]

Desired phenomenon:

- teacher task difficulty stays flat;
- reusable learner’s required examples decline.

---

# 25. Primary metric 3 — new composition after the lifetime

After training:

1. freeze shared/library parameters;
2. sample an unseen complete program composed from known hidden primitives;
3. initialize fresh task state;
4. adapt **only task-specific code**.

Evaluate after:

\[
0,1,2,4,8,16,32
\]

examples.

This directly asks whether the learner accumulated a computational language that makes a new composition cheap to express.

# 26. Primary metric 4 — retained description length

Report separately:

- global parameter count;
- per-task state;
- active operator count;
- route/program bits;
- quantized storage;
- FLOPs per prediction.

For a simple V1 code, use 8-bit quantized weights:

\[
D_{\mathrm{weights}}
=
8\times
\#\text{retained scalars}.
\]

Discrete task routes:

\[
D_{\mathrm{route}}
=
N_{\mathrm{tasks}}
L
\lceil\log_2K_{\mathrm{active}}\rceil.
\]

Dense task embeddings and continuous coefficients must also be counted.

Actually evaluate the quantized model before claiming that code length preserves behavior.

# 27. Functional primitive recovery

Because teacher operations are known, compare learned \(Q_j\) and teacher \(P_i\) on a large probe set:

\[
d_{ij}
=
\frac{
\mathbb E\|P_i(x)-Q_j(x)\|^2
}{
\operatorname{Var}(P_i(x))
}.
\]

Use Hungarian matching for a best one-to-one diagnostic, but also search short teacher compositions of depth 1–3.

A learned operator might correspond to:

\[
P_2\circ P_5
\]

rather than a single primitive.

The scientifically meaningful target is a **short functional explanation**, not exact label recovery.

---

# 28. Route recovery

After functional matching, compare learned task routes to teacher programs.

Report:

- exact sequence match;
- per-position match;
- edit distance;
- functional/behavioral equivalence.

Behavioral equivalence is more important than symbolic identity.

---

# 29. Specialization diagnostics

For discrete libraries record:

- operator usage frequency;
- routing entropy;
- tasks per operator;
- route positions per operator;
- pairwise functional distance.

Watch for:

### Collapse
Most tasks route through the same operator.

### Fragmentation
Every task effectively gets its own computation.

### Duplication
Many operator slots implement nearly the same function.

---

# 30. Benchmark validity checks

Before fancy models:

## Scratch-task test

Train an independent tiny model from scratch on every hidden task.

Examples-to-criterion should have no systematic trend with task index.

## Reverse-order test

Run the same world in reverse task order.

## Scrambled-ID test

Reassign opaque task IDs.

## Uniform output-scale test

Reject hidden primitives/programs with pathological output variance or saturation.

## Oracle test

The oracle must show strong late-life transfer.

If these fail, do not interpret model differences.

---

# 31. Separate task inference from operator quality

At several lifetime points, give a diagnostic model the **true route** but current learned operators.

This distinguishes:

- good library / bad route inference;
- bad library.

If oracle-route evaluation is excellent but learned routing is poor, focus on routing/program inference rather than redesigning primitives.

This is important because modular work has shown that discovering routing can itself be the bottleneck.

Relevant:
https://arxiv.org/abs/2407.12275

---

# 32. Hard routing must compete with soft routing

Discrete routing may simply be difficult to optimize.

**Soft Merging of Experts with Adaptive Routing (SMEAR)** demonstrates that differentiable expert composition can be more trainable than hard learned routing in some settings:

https://arxiv.org/abs/2306.03745

Therefore:

> hard routing failure is not evidence against reusable computation.

Always run the continuous/soft alternative.

# 37. Minimal teacher pseudocode

```python
class Primitive:
    def __init__(self, d=16, rank=8, alpha=0.35, seed=0):
        self.V = random_matrix(rank, d, seed)
        self.U = random_matrix(d, rank, seed + 1)
        self.b = random_vector(rank, seed + 2)
        self.alpha = alpha

    def __call__(self, z):
        return tanh(
            z
            + self.alpha
            * self.U
            @ tanh(self.V @ z + self.b)
        )


class Program:
    def __init__(self, primitive_ids):
        self.primitive_ids = primitive_ids

    def execute(self, library, x):
        z = x
        for primitive_id in self.primitive_ids:
            z = library[primitive_id](z)
        return z


class World:
    def __init__(self, seed, K=6, program_len=3, n_tasks=64):
        self.library = [
            Primitive(seed=hash((seed, k)))
            for k in range(K)
        ]

        self.tasks = sample_unique_programs(
            K=K,
            length=program_len,
            count=n_tasks,
            seed=seed,
        )

        self.task_ids = shuffled_opaque_ids(
            n_tasks,
            seed=seed + 1,
        )
```

# 38. Minimal lifetime pseudocode

```python
def run_lifetime(model, world, replay):
    results = []

    for task_index, task in enumerate(world.tasks):
        task_id = world.task_ids[task_index]
        model.begin_task(task_id)

        evaluate_and_log(model, task_id, task, n_seen=0)

        for n in range(1, 129):
            x = sample_input()
            y = task.execute(world.library, x)

            # Important: score before learning from the example.
            pred = model(task_id, x)
            log_prequential_loss(pred, y)

            replay_batch = replay.sample()

            model.update(
                task_id=task_id,
                x=x,
                y=y,
                replay=replay_batch,
            )

            replay.maybe_add(task_id, x, y)

            if n in {1,2,4,8,16,32,64,128}:
                evaluate_and_log(
                    model,
                    task_id,
                    task,
                    n_seen=n,
                )

    return results
```

# 41. Decision matrix

## Oracle wins, reusable model wins, dense lags

Proceed to \(ho\) sweep.

## Oracle wins, continuous basis wins, discrete fails

Focus on continuous operation manifolds/hypernetworks. Do not build a discrete compiler yet.

## Oracle wins, all learned reusable models fail

Routing/task inference is likely the bottleneck.

## Dense matches reusable models

Explicit modularity may be unnecessary. Use mech interp to ask whether dense training produced an implicit reusable computational basis.

## Reuse improves storage but not learning speed

The project becomes a compression result, not a learning-to-learn result.

## Benefit remains at \(ho=0\)

Assume benchmark confound until proven otherwise.

# 43. Novelty boundary

Do not claim that any of these individually are new:

- modular neural networks;
- reusable learned components;
- compositional routing;
- continual learning;
- MDL;
- learned latent programs;
- expansion/compression cycles.

The potentially novel research program is narrower:

> **Evaluate internal neural abstractions by the reduction they produce in lifetime/prequential learning cost, then allow the neural computational vocabulary itself to be compressed and structurally reorganized according to that criterion.**

ROW tests the assumptions needed before attempting that full system.

---

# 44. V1 go/no-go gate

Do **not** implement a neural compiler until all of the following are true:

1. Oracle compositor shows strong lifetime transfer.
2. At least one fixed reusable substrate beats a matched dense model on high-reuse worlds.
3. The advantage becomes substantially smaller as reuse decreases.
4. Novel-composition adaptation improves.
5. Results survive world/task-order changes.
6. We understand whether the gain comes from operator reuse, routing, lower forgetting, or raw capacity.

Only then ask:

> Can the learner discover the right amount and granularity of reuse itself?

If reusable learners do not become better learners in a world deliberately constructed from reusable computation, stop and diagnose that before adding architectural sophistication.

If they do, then the research question becomes:

> **Can the learner discover the appropriate computational vocabulary—and when to share versus specialize—without us specifying that vocabulary?**

That is where MDL, residual specialization, copy-on-write, merge/split, sleep/consolidation, and eventually meta-learned structural optimization become justified.

# 47. Research statement

> **Reusable Operator Worlds tests whether neural learners can convert recurring computational structure into a reusable internal vocabulary that reduces the cumulative cost of future learning. Rather than defining abstraction by human interpretability or module count, abstraction is evaluated by its causal contribution to future sample efficiency and its retained description cost.**

The first objective is deliberately modest:

> **Establish whether an explicit reusable computational substrate changes lifetime learning curves in a controlled world whose latent causal structure is known.**

Only if that succeeds should the project move toward dynamic neural refactoring, mechanistic interpretation of dense LLMs, or altered language-model training.
